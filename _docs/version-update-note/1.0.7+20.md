# 1.0.7+20 업데이트 노트

상태: 구현 완료 (릴리즈 준비, pubspec 1.0.7+20 반영)
작성 시작: 2026-07-24 / 마감 정리: 2026-08-16

## 요약

잠금화면 타이머를 양 플랫폼에 추가했다. iOS는 Live Activity(잠금화면 + 다이내믹 아일랜드), Android는 진행형 알림으로 구현했고, 앱을 열지 않아도 남은 시간 확인과 일시정지/종료가 가능하다.
그 외 가로모드 지원, 스킨 GIF 로딩 아키텍처 개선(성능), 다수 버그 수정이 포함됐다.

## 요구사항

- iOS 기본 타이머처럼, 잠금화면에 타이머 위젯을 띄우고 싶다. (참고 이미지: 타이머 숫자 + 일시정지/취소 버튼)
- 앱을 열지 않아도 잠금화면에서 남은 시간이 실시간으로 보여야 한다.

## 의사결정 흐름

### 1. 타이머 잠금화면 위젯 추가

- iOS에는 이 기능을 위한 전용 API가 있다: Live Activity(ActivityKit, iOS 16.1+). 참고 이미지가 정확히 이 형태다.
- 뽀모도로 타이머는 Live Activity에 잘 맞는 유스케이스라 채택.

### 2. iOS와 Android 형태 분리

- Android에는 Live Activity와 1:1로 동일한 API가 없다.
- Android에서 가장 가까운 대응품은 "진행형 알림(ongoing notification) + Chronometer"이다. 알림 안에서 시간이 자동 카운트다운되고 버튼도 넣을 수 있으나, iOS처럼 크고 자유로운 커스텀 카드가 아니라 정해진 알림 틀 안에서만 꾸밀 수 있다(캐릭터 일러스트 등 자유 디자인 불가).
- 결정: 두 플랫폼은 형태가 근본적으로 달라 분리한다. iOS를 먼저 진행하고, Android(진행형 알림)는 후속으로 별도 진행한다.

### 3. iOS 1차 범위: 미니멀, 스킨은 후속

- 앱의 핵심인 스킨(캐릭터)을 Live Activity에도 반영할지 논의.
- Live Activity는 정적 이미지만 가능(GIF 애니메이션 불가)하고, 앱과 위젯 간 이미지 공유(App Group) 설정이 추가로 필요해 작업량이 늘어난다.
- 결정: 1차는 미니멀 디자인(타이머 + 버튼)으로 파이프라인을 먼저 검증하고, 스킨 반영은 후속으로 얹는다.

### 4. 버튼: 일시정지 + 취소, iOS 17+ 에서만 노출

- 참고 이미지의 버튼은 일시정지(⏸)와 취소(✕) 두 개.
- 앱을 확인해보니 이미 pause/resume 동작이 존재한다: 정지 시 남은 시간을 유지하고, 다시 시작하면 이어서 진행한다. Live Activity 버튼을 이 동작에 매핑한다.
- 취소(✕)는 iOS 기본 타이머 표준을 따른다: 세션을 완전히 종료하고 위젯을 제거하며, 앱의 타이머는 처음 맞춘 시간으로 복귀한다.
- 잠금화면 위젯 안의 버튼이 실제로 동작하려면 iOS 17+가 필요하다(App Intent 기반). 결정: 버튼은 iOS 17.0+ 에서만 노출·동작하고, iOS 16.1~16.4는 카운트다운 표시만 한다.

### 5. 구현 방식: live_activities 패키지 + URL scheme (트레이드오프 있음)

- Flutter(Dart)에서 Swift의 ActivityKit을 직접 못 부르므로 다리가 필요하다. 검증된 `live_activities` pub 패키지를 사용하기로 결정(브리지 보일러플레이트를 직접 안 짜도 되고, 앱이 이미 외부 패키지를 여럿 쓰고 있어 부담이 적다).
- 한계 발견: 이 패키지가 제공하는 버튼 상호작용은 URL scheme(딥링크) 기반이다. "iOS 17 App Intent로 앱을 안 열고 잠금화면에서 바로 처리"하는 방식은 패키지가 기본 제공하지 않는다.
- 두 갈래:
  - A(URL scheme): 버튼 탭 시 앱이 순간 열려 기존 Dart 로직으로 처리 후 위젯 갱신. 타이머 제어 로직이 Dart 한 곳에만 있어 기존 구조와 일치하고 버그 위험이 낮다. 단, 버튼 누를 때마다 앱이 잠깐 뜬다.
  - B(App Intent): 앱을 안 열고 잠금화면에서 바로 처리(iOS 기본 타이머 UX). 단, pause/resume/cancel 로직을 Swift로도 중복 구현해야 해 작업량·유지보수·버그 위험이 크게 늘어난다.
- 결정: A로 진행한다. 최소 코드·단일 소스 원칙과 "1차 파이프라인 검증" 방향에 맞다. 트레이드오프(버튼 탭 시 앱이 순간 열림)를 감수하고, "앱 안 열고 제어"가 정말 필요하면 후속에서 B로 고도화한다.

## 구현 내용

### iOS 잠금화면 타이머 (Live Activity)

- `live_activities` 패키지 + Widget Extension 타겟(iOS 16.1+)으로 잠금화면·다이내믹 아일랜드에 실시간 카운트다운 표시.
- 버튼(일시정지/재개, 종료)은 계획했던 A안(URL scheme)에서 B안(AppIntent, iOS 17+)으로 전환 — 앱을 열지 않고 잠금화면에서 바로 동작한다. (전환 사유는 "변경 이력" 참고)
- 위젯 UI를 손그림 시안으로 리디자인(버튼 이미지·테마 색상·전용 폰트, App Group으로 에셋 공유).
- 타이머 종료(0초) 처리: iOS 26+는 AlarmKit으로 분기 — 첫 시작 시 알람 권한을 요청하고, 시스템이 카운트다운 위젯을 관리하며, 0초에 알람 알럿(전용 종료음)이 울리고 중지하면 위젯·아일랜드가 자동으로 사라진다(무음모드 관통, 이 경로에서는 로컬 종료 알림 생략). iOS 26 미만·권한 거부 시는 기존 로컬 알림 경로 유지.

### Android 잠금화면 진행형 알림

- 진행형 알림(ongoing notification)으로 잠금화면·알림창에 남은 시간 실시간 표시, 일시정지/재개·종료 버튼 제공(MethodChannel + BroadcastReceiver).
- 커스텀 레이아웃 대신 테마 적응 텍스트 색상 사용(다크/라이트 대응), 전용 폰트 적용.
- 앱 시작 시 Android 13+ 알림 권한(POST_NOTIFICATIONS) 요청 추가.

### 가로모드 지원

- 회전 잠금 해제 및 가로 전용 레이아웃 분기. 최종적으로 영역분할 방식 대신 배경 앵커 레이아웃으로 정착, 가로 전용 배경 이미지(`_landscape`) 도입.
- 회전 시 다이얼 터치 각도 어긋남·드래그 프레임 드랍 수정.

### 스킨 GIF 아키텍처 개선 (성능)

- 모든 스킨을 동시에 빌드하던 구조에서 현재 스킨만 빌드하고 나머지는 백그라운드 프리캐시하도록 전환.
- apple/wash 모션을 자체 타이머 대신 타이머 상태에서 유도하는 순수함수 구조로 정리, 스킨 전환 시 정지 화면 최소화(단계적 디코딩).

### 버그 수정

- 백그라운드/잠금 복귀 시 stale 데이터(leaveMillisec, sync 스냅샷)가 타이머를 00:00으로 덮어쓰거나 잘못 동기화하던 문제 수정 (iOS·Android 각각).
- 다이얼 재설정 중 낡은 startSec으로 blink 구간이 계산되던 문제 수정(설정 중엔 대기 포즈 고정).
- 회전 시 BottomButtonWidet dispose assertion, 가로 다이얼 overflow 등 레이아웃 이슈 수정.

## 이슈와 해결

- Live Activity 생성이 계속 실패 → Push Notifications capability 누락이 원인. capability 추가로 해소(원격 푸시는 사용하지 않음, ActivityKit 요구사항).
- Widget Extension 추가 후 빌드 순환 의존성 → Embed Foundation Extensions 페이즈 순서 조정으로 해소.
- 잠금화면 버튼 탭이 URL scheme 방식에선 앱이 순간 열리는 UX 문제 → AppIntent 3종을 양쪽 타겟에 등록하고 MethodChannel + 프로세스 내 핑 브리지로 네이티브↔Dart 상태 동기화(reconcile 순수 함수)를 구축해 해결.
- gif_view가 프레임 디코딩을 마운트 시점에 하므로 프리캐시만으로는 스킨 전환 정지 화면을 완전히 없앨 수 없음 → 초기 모션 우선 디코딩(단계적 로딩)으로 완화. 한계는 문서에 기록.
- 타이머가 0초로 자연종료돼도 위젯이 남는 문제 → '끝!' 문구 표시(staleDate)로 우회하려 했으나 staleDate가 만료 순간 재렌더링을 보장하지 않아 실패(iOS 알려진 한계). iOS 26+ AlarmKit 분기로 전환해 시스템이 종료 알럿과 위젯 정리를 담당하게 해결하고 '끝!' 표시는 제거. 알람음은 중지 전까지 반복되는 사양(1회 재생 옵션 없음)이라 무음 5초를 덧붙인 전용 파일(진폭 80%)로 반복 간격을 완화.

## 변경 이력

- 2026-07-24: 초기 기획·설계 확정. (요구사항 → iOS/Android 분리 → iOS 미니멀 1차 → 버튼 17+ → 패키지 A안)
- 이후: 버튼 구현을 A안(URL scheme)에서 B안(AppIntent)으로 전환. 버튼 탭마다 앱이 잠깐 열리는 UX가 iOS 기본 타이머 기대치와 어긋났고, 실제 구현해 보니 reconcile 순수 함수 + MethodChannel 동기화로 중복 로직 위험을 관리할 수 있다고 판단.
- 이후: "iOS 먼저, Android 후속" 계획이었으나 Android 진행형 알림까지 이번 버전에 포함.
- 이후: 위젯 미니멀 디자인 계획을 손그림 시안 리디자인으로 확장(스킨 캐릭터 반영은 여전히 후속).
- 2026-08-16: 자연종료 시 위젯이 남는 한계를 iOS 26+ AlarmKit 분기로 해결. staleDate 기반 '끝!' 문구 표시는 동작하지 않아 제거.

## 남은 과제 (이번 범위 밖)

- Live Activity에 스킨(캐릭터/색상) 반영.
- 가로모드 전용 에셋 배선 (feature/landscape-mode 브랜치에서 이어감).
- iOS 26 잠금화면 위젯 다크 고정 버그 대응 확인.
- AlarmKit 알람음 반복 사양(1회 재생 불가) 개선 여지 모니터링 — 현재는 무음 패딩으로 간격만 완화.
- Android 종료음 실기기 확인 및 유예했던 minor 항목들.

## 보고용 초안

이번 1.0.7+20은 "앱을 안 열어도 타이머가 보이게"가 핵심입니다. iOS는 잠금화면과 다이내믹 아일랜드에 실시간 타이머(Live Activity)를 띄우고, 잠금화면에서 바로 일시정지/종료할 수 있습니다(버튼은 iOS 17+). 원래 버튼을 누르면 앱이 잠깐 열리는 간단한 방식으로 계획했지만, iOS 기본 타이머 수준의 UX를 위해 앱을 열지 않고 동작하는 AppIntent 방식으로 고도화했습니다. Android도 후속으로 미루지 않고 이번에 함께 넣었습니다 — 잠금화면 진행형 알림으로 남은 시간과 일시정지/종료 버튼을 제공합니다. 그 외 가로모드 지원, 스킨 전환 성능 개선(현재 스킨만 로드), 백그라운드 복귀 시 타이머가 어긋나던 버그 수정이 포함됐습니다. 위젯에 캐릭터 스킨을 입히는 건 다음 버전 과제로 남겼습니다.

## 담당자 공유 메시지 (최종본, 2026-08-16)

안녕하세요! 조구만 뽀모도로 1.0.7 업데이트 작업이 완료되어 공유드립니다. 🍅

1. 잠금화면 타이머 (iOS / Android 모두)

- 타이머를 켜두고 폰을 잠가도, 잠금화면에서 남은 시간이 실시간으로 보입니다
- 잠금화면에서 바로 일시정지/다시시작, 종료가 가능합니다. (iOS는 다이내믹 아일랜드에도 표시돼요)

2. 가로모드 지원

- 폰을 눕히면 가로 화면에 맞는 레이아웃으로 자동 전환됩니다.

3. 사용성 개선

- 스킨(캐릭터) 전환이 더 빠르고 부드러워졌습니다.

시안과 조금 다르게 구현된 부분도 공유드려요. 잠금화면 위젯은 iOS/Android가 제공하는 틀 안에서 그리는 영역이라, 그 안에서 시안의 느낌을 최대한 살리는 방향으로 작업했습니다.

iOS

- 시간 표시부는 iOS가 직접 그려주는 영역이라 간격을 자유롭게 조절할 수 없는데, 폰트와 배치를 조정해 시안에 최대한 가깝게 맞췄습니다
- 다이내믹 아일랜드의 Progress Bar 는 시스템 기본 형태를 사용하되, 하이라이트 색상을 조구만 노란색으로 맞춰 브랜드 톤을 유지했습니다
- iOS 26부터는 Apple의 새 알람 시스템(AlarmKit)을 따르게 되어, 타이머 종료 시 시스템 표준 종료 팝업이 함께 표시됩니다.

Android

- 고정 알림은 Android 알림 규격 안에서 꾸미도록 되어 있어서, 그 범위 안에서 전용 폰트와 버튼 디자인을 적용해 시안 분위기를 최대한 살렸어요.

양쪽 스토어에 심사 제출까지 마쳤고, 심사가 통과되는 대로 순차 배포됩니다. TestFlight에서 미리 사용하실 수 있습니다.

참고로 이번부터 iOS 최소 지원 버전이 iOS 15로 올라갑니다(Apple 정책 대응). iOS 13~14 기기는 새 업데이트를 못 받지만, 해당 버전 글로벌 점유율이 1% 미만이라 영향은 거의 없어요.

## 심사 메모 (App Review Notes)

한국어 원문:

- 이 앱은 로그인/계정 없이 모든 기능을 바로 사용할 수 있는 뽀모도로 타이머입니다.
- 이번 업데이트의 주요 변경은 Live Activity(ActivityKit) 추가입니다. 타이머가 실행 중일 때만 잠금화면과 다이내믹 아일랜드에 남은 시간이 표시되며, 타이머를 종료하면 사라집니다.
- 테스트 방법: 앱 실행 → 다이얼을 돌려 시간 설정 → 시작 버튼 → 기기를 잠그면 잠금화면에서 타이머를 확인할 수 있습니다. iOS 17 이상에서는 위젯의 일시정지/종료 버튼이 동작합니다(iOS 16.1~16.x는 표시만 됨).
- iOS 26 이상에서는 타이머 종료(0초) 알림에 AlarmKit을 사용합니다. 첫 타이머 시작 시 알람 권한을 요청하며(NSAlarmKitUsageDescription), 0초에 시스템 알람이 울리고 중지하면 위젯이 함께 사라집니다. 권한을 거부하면 아래의 로컬 알림 방식으로 동작합니다.
- Push Notifications capability는 ActivityKit(Live Activity) 요구사항으로 추가된 것이며, 원격 푸시 알림은 전송하지 않습니다. 알림은 타이머 종료를 알리는 로컬 알림만 사용합니다(iOS 26 이상에서 AlarmKit 사용 시에는 로컬 알림 대신 알람으로 알립니다).
- App Group은 앱과 위젯 익스텐션 간 타이머 상태·에셋 공유 용도입니다.

영문(제출용):

- This is a Pomodoro timer app. No login or account is required; all features are available immediately.
- The main change in this update is Live Activity (ActivityKit) support. While a timer is running, the remaining time is shown on the Lock Screen and in the Dynamic Island, and it disappears when the timer is stopped.
- How to test: launch the app, rotate the dial to set a duration, tap start, then lock the device. The timer appears on the Lock Screen. On iOS 17+, the pause/stop buttons on the widget work via App Intents (on iOS 16.1–16.x the widget is display-only).
- On iOS 26+, the app uses AlarmKit for the timer-completion alert. The first time a timer starts, the app requests alarm authorization (NSAlarmKitUsageDescription). When the countdown reaches zero, a system alarm alerts, and stopping it also dismisses the widget. If authorization is denied, the app falls back to the local-notification behavior below.
- The Push Notifications capability was added solely because ActivityKit requires it; the app does not send remote push notifications. Only local notifications are used (to notify when the timer ends); on iOS 26+ with AlarmKit authorized, the completion alert comes from AlarmKit instead of a local notification.
- The App Group is used to share timer state and assets between the app and the widget extension.
