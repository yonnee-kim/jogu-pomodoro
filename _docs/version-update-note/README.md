# 버전 업데이트 노트 (version-update-note)

## 목적

버전별 개발 내용을 팀원(비개발자 포함)과 공유하고 진행 상황을 기록하기 위한 폴더다.
각 버전이 "원래 이렇게 기획했는데, 이런 이유로 이렇게 개발했다"를 스스로 설명할 수 있도록 상세히 기록한다.
최종 목표는 이 문서를 바탕으로 팀 공유용 자연어 보고 메시지를 작성하는 것이다.

## 파일 규칙

- 파일명은 `pubspec.yaml`의 버전 그대로 사용한다. 예: `1.0.7+20.md`.
- 한 버전당 하나의 파일. 여러 세션에 걸쳐 같은 파일을 이어서 채운다.
- 표(table)를 쓰지 않고 리스트로 간결하게 작성한다.
- 진행 중 결정이 바뀌면 지우지 말고 "변경 이력"에 남긴다. 왜 바뀌었는지가 보고의 핵심이다.

## 각 노트에 담을 항목

- 요약: 이번 버전에서 무엇을 했는지 한두 줄.
- 요구사항: 사용자가 원래 무엇을 요청했는지.
- 의사결정 흐름: 어떤 선택지가 있었고 무엇을 왜 골랐는지. 트레이드오프 포함.
- 구현 내용: 실제로 무엇을 만들었는지.
- 이슈와 해결: 진행 중 생긴 문제와 대응.
- 변경 이력: 중간에 방향이 바뀐 것.
- 남은 과제: 이번 범위 밖으로 미룬 것.
- 보고용 초안: 위 내용을 팀원에게 전할 자연어 메시지 초안.

## 다른 세션에서 이어 쓸 때

- 해당 버전 파일이 있으면 새로 만들지 말고 이어서 채운다.
- 새 버전이면 이 규칙대로 새 파일을 만든다.
- 이전 버전 노트의 "남은 과제"를 확인해 다음 버전 계획에 반영한다.
